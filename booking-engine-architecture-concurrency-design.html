Booking Lifecycle — Hold → Pay → Confirm

Step 1 Browse
GET /availability/:id
Slots cached 60s in Redis with live "held" status
Step 2 Hold Slot
Acquire Redis lock (SET NX PX 600s)
Re-check status inside lock
Create pending Booking
Step 3 Payment
Razorpay order created
Client opens payment modal
10-min window
Step 4 Confirm
Verify HMAC signature
Mongoose transaction:
slot → booked, booking → confirmed
Step 5 Cleanup
Release Redis lock
Clear hold record
Invalidate cache

Concurrency Safety — Two Layers

Layer 1 — Redis distributed lock (primary guard)

SET NX PX acquires the lock atomically. Concurrent requests that fail to acquire after retryCount attempts receive HTTP 409. Lua script on release ensures only the original holder can free the lock — prevents a late release from evicting a lock re-acquired by another request.

Layer 2 — MongoDB unique partial index (safety net)

Index on (interviewer, scheduledDate, startTime) with partial filter on active statuses. Even if the Redis lock is somehow bypassed, the DB write fails with E11000 and the caller receives 409.

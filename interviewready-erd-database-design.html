Design Decisions & Constraints

DecisionDetail
MongoDB document storeAll collections use Mongoose schemas. Embedded sub-documents (participants, codeSnapshots, chatLog) avoid expensive joins for session data accessed together.
DenormalisationinterviewerUser on AvailabilitySlot and interviewer on InterviewSession are denormalised ObjectId refs to avoid deep-chain populate in hot read paths.
Redis distributed locksSlot booking uses Redis locks (redisLockService) to prevent double-booking under concurrent requests before the MongoDB write.
Partial unique index on subscriptionsOnly one active subscription per user is enforced at the DB level via a partial filter index, allowing historical records.
Mutex on paymentsExactly one of booking or subscription must be set on each payment document — enforced at application layer in paymentService.
TTL indexesNotifications auto-expire after 90 days; AvailabilitySlot past entries expire via TTL on endDateTime; password-reset and email-verification tokens also have TTL fields.
Soft delete on usersdeletedAt field enables GDPR-compliant soft deletion; isDeleted virtual computed from it.
select:false sensitive fieldspassword, refreshTokens, loginAttempts, bankDetails, razorpaySignature, and PII sub-fields are excluded from default queries.
Rating denorm on Interviewerrating.average and rating.count are maintained by updateRating() method on every new review to avoid aggregation on every profile load.
Compound unique on bookingsInterviewer + scheduledDate + startTime is unique with a partial filter excluding cancelled/no-show statuses, preventing double-booking while allowing re-booking after cancellation.
